Câu 1 Junior Express.js Fundamentals

What is Express.js, and how does it relate to Node.js?

🇻🇳 Express.js là gì và mối quan hệ của nó với Node.js?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Express.js là framework ứng dụng web tối giản, linh hoạt và phổ biến nhất được xây dựng trên nền tảng Node.js. Trong khi Node.js cung cấp môi trường runtime và module http ở tầng thấp, Express.js cung cấp một lớp trừu tượng (abstraction layer) cấp cao bao gồm hệ thống định tuyến (Routing), chuỗi xử lý Middleware, phân tích dữ liệu yêu cầu và xử lý phản hồi HTTP trực quan.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Mối quan hệ: Node.js là Engine/Runtime; Express.js là Framework/Thư viện chạy bên trong runtime đó.
2. Tại sao không dùng `http` thuần: Khi dùng `http` thuần, lập trình viên phải tự parse URL, tự gom buffer dữ liệu `req.on('data')`, tự map method và path bằng nhiều khối `if/else`, tự cấu hình header MIME types. Express đóng gói tất cả các thao tác này vào các API trực quan như `app.get()`, `req.body`, `res.json()`.
3. Triết lý Unopinionated: Express không áp đặt cấu trúc thư mục, kiến trúc MVC hay bất kỳ ORM nào.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

// Express trừu tượng hóa toàn bộ việc xử lý HTTP của Node.js
app.get('/api/welcome', (req, res) => {
  res.status(200).json({
    framework: 'Express.js',
    runtime: 'Node.js',
    message: 'Chào mừng bạn đến với REST API tối giản!'
  });
});

app.listen(3000, () => console.log('Server chạy tại port 3000'));
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Nhớ nhấn mạnh: 'Express không thay thế Node.js mà là một tiện ích bổ trợ xây dựng trực tiếp trên core module http của Node.js'.
Câu 2 Junior Express.js Fundamentals

Explain the concept of middleware in Express.js.

🇻🇳 Khái niệm Middleware trong Express.js hoạt động như thế nào?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Middleware là các hàm trung gian nằm trong chu trình Request-Response (Vòng đời từ khi client gửi request đến khi server trả response). Một middleware có quyền truy cập vào 3 tham số: req (Request object), res (Response object), và next (hàm kích hoạt middleware tiếp theo trong chuỗi).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Bốn nhiệm vụ của Middleware:
- Thực thi bất kỳ đoạn mã nào (ví dụ logging, kiểm tra bảo mật).
- Biến đổi hoặc gắn thêm thuộc tính vào `req` và `res` (ví dụ `req.user = decodedToken`).
- Kết thúc chu trình request-response (gọi `res.send()`, `res.json()`).
- Gọi `next()` để chuyển quyền thực thi cho middleware kế tiếp.
2. Nguy cơ treo request: Nếu middleware không kết thúc response và cũng không gọi `next()`, request sẽ bị đứng yên mãi mãi dẫn đến timeout.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

// Middleware ghi nhật ký request
const requestLogger = (req, res, next) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.originalUrl}`);
  next(); // BẮT BUỘC gọi next() để tiếp tục luồng!
};

app.use(requestLogger);

app.get('/hello', (req, res) => {
  res.send('Xin chào!');
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Luôn nhớ: Thứ tự khai báo middleware (`app.use`) trong Express cực kỳ quan trọng! Middleware nào khai báo trước sẽ chạy trước.

How would you set up a basic Express.js application?

🇻🇳 Cách thiết lập một ứng dụng Express.js cơ bản từ đầu?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Thiết lập ứng dụng gồm 4 bước cơ bản: (1) Khởi tạo dự án bằng npm init -y, (2) Cài đặt package npm install express, (3) Tạo file index.js, import Express, khởi tạo instance const app = express(), định nghĩa route mẫu, và (4) Gọi app.listen(PORT) để lắng nghe kết nối.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Cấu hình Scripts: Thêm `"start": "node index.js"` và `"dev": "nodemon index.js"` vào `package.json`.
2. Kiểm tra Health Endpoint: Luôn tạo route `/health` để hệ thống giám sát (Load Balancer, Kubernetes) kiểm tra xem server có đang sống không.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();
const PORT = process.env.PORT || 3000;

// Middleware parse JSON
app.use(express.json());

// Health check endpoint
app.get('/health', (req, res) => {
  res.json({ status: 'UP', timestamp: new Date() });
});

app.listen(PORT, () => {
  console.log(`Express application đang chạy tại http://localhost:${PORT}`);
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Luôn dùng `process.env.PORT || 3000` thay vì fix cứng cổng 3000 để server có thể chạy linh hoạt khi deploy lên Heroku, AWS, hoặc Docker.
Câu 4 Junior Express.js Fundamentals

What is the purpose of the app.use() function?

🇻🇳 Mục đích và cơ chế của hàm `app.use()` trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
app.use() là hàm dùng để đăng ký một hoặc nhiều middleware vào pipeline xử lý của ứng dụng Express. Nó có thể áp dụng cho toàn bộ ứng dụng (Application-level) hoặc giới hạn cho một tiền tố đường dẫn cụ thể (ví dụ: app.use('/api', apiRouter)).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Khác biệt với `app.get()` / `app.post()`: `app.use()` khớp với MỌI HTTP Method (GET, POST, PUT, DELETE, OPTIONS...) và khớp với tiền tố đường dẫn (Prefix matching).
2. Ví dụ: `app.use('/users', ...)` sẽ tự động khớp với `/users`, `/users/123`, `/users/profile/edit`.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

// 1. Áp dụng toàn cục cho tất cả mọi request
app.use(express.json());

// 2. Chỉ áp dụng cho các route bắt đầu bằng /admin
app.use('/admin', (req, res, next) => {
  console.log('Truy cập khu vực quản trị Admin!');
  next();
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Thứ tự đặt `app.use()` quyết định luồng chạy. Nếu đặt `app.use(express.json())` sau các route handlers, `req.body` trong các route đó sẽ bị `undefined`!

How do you serve static files using Express.js?

🇻🇳 Cách phục vụ các file tĩnh (Static Files: CSS, JS, hình ảnh) trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Express cung cấp sẵn built-in middleware express.static(root, [options]). Bạn chỉ cần chỉ định thư mục chứa file tĩnh (ví dụ thư mục public), Express sẽ tự động phục vụ các file đó với đúng MIME type và ETag header.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Tuyệt đối dùng `path.join`: Luôn kết hợp với `path.join(__dirname, 'public')` để đảm bảo đường dẫn chính xác khi chạy script từ các thư mục khác nhau.
2. Tiền tố ảo (Virtual Path Prefix): Có thể gắn mount path: `app.use('/static', express.static('public'))` để truy cập file qua URL `/static/images/logo.png`.
3. Caching: Cấu hình `maxAge` để trình duyệt lưu cache, giảm tải cho server.
💻 Code Ví Dụ Minh Họa & Output 
const path = require('node:path');
const express = require('express');
const app = express();

// Phục vụ file tĩnh từ thư mục 'public' với cache 1 ngày
app.use('/assets', express.static(path.join(__dirname, 'public'), {
  maxAge: '1d',
  etag: true
}));

// Khi đó file /public/css/style.css sẽ truy cập qua:
// http://localhost:3000/assets/css/style.css
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Trong môi trường Production lớn, hãy để Nginx hoặc AWS CloudFront/S3 phục vụ file tĩnh thay vì để Express gánh, giúp tiết kiệm CPU cho Node.js.
Câu 6 Junior Express.js Fundamentals

Discuss the difference between app.get() and app.post() in Express.js.

🇻🇳 Sự khác biệt giữa `app.get()` và `app.post()` trong Express.js?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
app.get() dùng để định nghĩa handler cho HTTP GET Request (dùng để tìm nạp / truy vấn dữ liệu từ server mà không làm thay đổi trạng thái hệ thống). app.post() dùng để định nghĩa handler cho HTTP POST Request (dùng để gửi dữ liệu từ client lên server để tạo mới tài nguyên hoặc kích hoạt tác vụ).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Vị trí truyền dữ liệu:
- GET: Dữ liệu gửi qua URL Query string (`req.query`), hiển thị rõ ràng trên thanh địa chỉ trình duyệt, có giới hạn độ dài URL (~2048 ký tự), có thể bị lưu vào Browser History và Cache.
- POST: Dữ liệu gửi ẩn trong Message Body (`req.body`), không giới hạn độ dài khắt khe, không bị browser cache tự ý.
2. Tính lũy thoái (Idempotence): GET là Safe & Idempotent (gọi nhiều lần kết quả không đổi, không gây side-effect). POST là Non-idempotent (gọi 2 lần sẽ tạo ra 2 đơn hàng khác nhau).
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();
app.use(express.json());

// GET: Đọc dữ liệu (Query params)
app.get('/api/search', (req, res) => {
  const keyword = req.query.q;
  res.json({ results: [`Kết quả cho: ${keyword}`] });
});

// POST: Ghi dữ liệu (Request Body)
app.post('/api/orders', (req, res) => {
  const { productId, quantity } = req.body;
  res.status(201).json({ success: true, orderId: 999 });
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Tuyệt đối không bao giờ dùng `GET` để thực hiện các thao tác nhạy cảm như xóa dữ liệu hoặc đăng nhập (vì mật khẩu sẽ bị lộ trên URL và Access Logs).
Câu 7 Junior Express.js Fundamentals

How do you retrieve the URL parameters from a GET request in Express.js?

🇻🇳 Cách lấy các tham số URL (Route Parameters) trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Sử dụng dấu hai chấm : khi định nghĩa đường dẫn route (ví dụ: /users/:userId/posts/:postId). Trong route handler, các giá trị này sẽ tự động được Express trích xuất và lưu dưới dạng đối tượng khóa-giá trị trong req.params.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Kiểu dữ liệu: Tất cả các giá trị trong `req.params` mặc định đều là kiểu Chuỗi (`string`). Nếu cần tính toán hoặc so sánh ID số nguyên, bạn phải tự ép kiểu bằng `parseInt(req.params.id, 10)` hoặc `Number()`.
2. Tham số tùy chọn: Thêm dấu chấm hỏi sau tên param: `/users/:userId?` (userId có thể có hoặc không).
3. Regex trong params: Cho phép ràng buộc định dạng ngay trên route: `app.get('/users/:id(\\d+)', ...)` (chỉ khớp nếu id là các chữ số).
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

// Định nghĩa route có 2 route parameters
app.get('/api/users/:userId/orders/:orderId', (req, res) => {
  const { userId, orderId } = req.params;
  
  res.json({
    userId: parseInt(userId, 10),
    orderId: orderId,
    timestamp: Date.now()
  });
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Phân biệt rõ: `req.params` là phần động của URL path (`/users/:id`), còn `req.query` là các tham số sau dấu hỏi chấm (`/users?role=admin`).

What are route handlers, and how would you implement them?

🇻🇳 Route Handlers trong Express là gì và cách triển khai linh hoạt?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Route Handler là hàm hoặc một mảng các hàm được thực thi khi một HTTP request khớp với đường dẫn (path) và phương thức (method) cụ thể. Express cho phép truyền nhiều hàm xử lý kế tiếp nhau cho cùng một route bằng cách sử dụng next().
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Chuỗi Handler (Chaining Handlers): Bạn có thể truyền 1 hàm, nhiều hàm phân cách bằng dấu phẩy, hoặc 1 mảng các hàm.
2. `next('route')`: Một tính năng đặc biệt! Nếu bạn gọi `next('route')`, Express sẽ bỏ qua tất cả các handler còn lại trong cụm route hiện tại và nhảy sang route tiếp theo khớp đường dẫn.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

const checkPermission = (req, res, next) => {
  req.isAdmin = true;
  next();
};

const validatePayload = (req, res, next) => {
  console.log('Payload hợp lệ');
  next();
};

// Truyền chuỗi nhiều handlers cho 1 route
app.post('/api/products', checkPermission, validatePayload, (req, res) => {
  res.send('Sản phẩm đã được tạo bởi Admin!');
});
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Áp dụng mẫu thiết kế này để chia nhỏ việc kiểm tra quyền (Authorization), validate dữ liệu và business logic thành các hàm riêng biệt, dễ viết unit test.

How do you enable CORS in an Express.js application?

🇻🇳 Cách kích hoạt và cấu hình CORS (Cross-Origin Resource Sharing) trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
CORS là cơ chế an ninh của trình duyệt ngăn chặn các trang web ở domain này gọi API sang domain khác. Trong Express, cách chuẩn mực nhất là sử dụng package cors. Ta có thể cho phép tất cả các domain hoặc chỉ định danh sách Whitelist các domain tin cậy.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Preflight Request: Với các method như PUT, DELETE hoặc khi có custom headers, trình duyệt tự động gửi một request `OPTIONS` trước để thăm dò server có cho phép không. Middleware `cors` tự động phản hồi status 204 cho preflight này.
2. Credentials: Nếu frontend gửi Cookie hoặc Authorization header, phải cấu hình `credentials: true` và `origin` không được phép là `'*'`. Khách hàng phải là domain cụ thể.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const cors = require('cors');
const app = express();

const whitelist = ['https://myfrontend.com', 'http://localhost:5173'];
const corsOptions = {
  origin: function (origin, callback) {
    // Cho phép các tool như Postman (origin undefined) hoặc domain trong whitelist
    if (!origin || whitelist.indexOf(origin) !== -1) {
      callback(null, true);
    } else {
      callback(new Error('Bị chặn bởi chính sách bảo mật CORS'));
    }
  },
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'DELETE']
};

app.use(cors(corsOptions));
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Lỗi CORS là lỗi của TRÌNH DUYỆT, không phải lỗi của Node server. Postman hoặc curl không bao giờ bị lỗi CORS vì chúng không áp dụng chính sách Same-Origin Policy.

Explain the use of next() in Express.js middleware.

🇻🇳 Giải thích vai trò của hàm `next()` trong Middleware của Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
next() là hàm điều phối cốt lõi của Express. Khi được gọi, nó chuyển quyền điều khiển sang middleware tiếp theo trong ngăn xếp (middleware stack). Nếu không gọi next() (và cũng không gửi response về cho client), request sẽ bị treo vĩnh viễn.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Chuyển tiếp lỗi: Nếu truyền bất kỳ tham số nào vào `next(err)` (ngoại trừ chuỗi `'route'`), Express sẽ coi đó là một LỖI và ngay lập tức bỏ qua toàn bộ các middleware thông thường còn lại để nhảy thẳng đến Error-handling Middleware gần nhất!
2. `next('router')`: Bỏ qua instance Router hiện tại.
💻 Code Ví Dụ Minh Họa & Output 
const express = require('express');
const app = express();

app.use((req, res, next) => {
  const authHeader = req.headers['authorization'];
  if (!authHeader) {
    // ⚠️ Truyền Error vào next() để nhảy thẳng đến Error Handler

});

How would you implement caching in an Express.js application?

🇻🇳 Cách triển khai cơ chế Caching trong ứng dụng Express.js?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Caching trong Express được triển khai ở nhiều tầng: (1) HTTP Client Caching (gửi header Cache-Control và ETag), (2) In-Memory Caching phía server (dùng Redis hoặc NodeCache cho các kết quả tính toán đắt đỏ), và (3) Reverse Proxy / CDN Caching (Cloudflare, Nginx lưu trữ cache HTML/JSON ở rìa mạng).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Redis Cache Middleware Pattern:
- Khi có request GET đến: Lấy URL làm cache key, kiểm tra Redis.
- Nếu Cache Hit: Trả về dữ liệu từ Redis ngay trong 1ms!
- Nếu Cache Miss: Chuyển sang route handler thực thi query DB, lưu kết quả vào Redis với thời gian sống TTL (Time-To-Live), sau đó trả về cho client.
2. Cache Invalidation: Bắt buộc xóa cache tương ứng trong Redis mỗi khi có request POST, PUT, DELETE làm thay đổi dữ liệu.
💻 Code Ví Dụ Minh Họa & Output 
const { createClient } = require('redis');
const redisClient = createClient();
redisClient.connect();

// Middleware Caching tự động cho Express
function cacheMiddleware(ttlSeconds = 60) {
  return async (req, res, next) => {
    if (req.method !== 'GET') return next();

    const key = `cache:${req.originalUrl}`;
    const cachedData = await redisClient.get(key);

    if (cachedData) {
      res.setHeader('X-Cache', 'HIT');
      return res.json(JSON.parse(cachedData));
    }

    res.setHeader('X-Cache', 'MISS');
    // Ghi đè hàm res.json để tự động lưu cache trước khi trả kết quả
    const originalJson = res.json.bind(res);
    res.json = (body) => {
      redisClient.setEx(key, ttlSeconds, JSON.stringify(body));
      return originalJson(body);
    };

    next();
  };
}

app.get('/api/products', cacheMiddleware(300), async (req, res) => {
  // Query DB tốn 500ms...
  res.json({ products: [] });
});

// Middleware chuẩn hóa lỗi Database
app.use((err, req, res, next) => {
  // Bắt lỗi trùng Unique Key của MongoDB (E11000)
  if (err.code === 11000) {
    const field = Object.keys(err.keyValue)[0];
    return res.status(409).json({

  if (err.name === 'ValidationError') {

    return res.status(400).json({ error: 'Dữ liệu không hợp lệ', details: errors });
  }

  res.status(500).json({ error: 'Lỗi cơ sở dữ liệu nội bộ' });
});

What are the advantages of using a database pooling mechanism in an Express.js app?

🇻🇳 Ưu điểm của cơ chế Connection Pooling khi kết nối Database trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Connection Pooling duy trì một nhóm các kết nối TCP tới Database đã được mở sẵn và giữ ở trạng thái nhàn rỗi. Khi có request cần truy vấn, nó mượn một kết nối từ pool, thực thi xong trả lại pool cho request khác tái sử dụng. Ưu điểm: (1) Loại bỏ chi phí đắt đỏ của quá trình bắt tay TCP và chứng thực mỗi lần truy vấn, (2) Giảm đáng kể độ trễ (latency), và (3) Giới hạn số lượng kết nối tối đa để bảo vệ Database không bị quá tải sập nguồn.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Chi phí bắt tay: Mở một kết nối TCP/TLS và xác thực mật khẩu với Postgres mất từ 30ms đến 100ms. Dùng pool giúp thời gian lấy kết nối giảm xuống chỉ còn < 1ms!
2. Cấu hình tối ưu: Thiết lập `max: 20` (số kết nối tối đa) và `idleTimeoutMillis: 30000`.
💻 Code Ví Dụ Minh Họa & Output 
const { Pool } = require('pg');

// Khởi tạo Connection Pool cho PostgreSQL trong Express
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20, // Tối đa 20 kết nối đồng thời
  idleTimeoutMillis: 30000,
  connectionTimeoutMillis: 2000,
});

app.get('/api/data', async (req, res, next) => {
  try {
    // Mượn connection từ pool, query xong tự động trả lại
    const result = await pool.query('SELECT NOW()');
    res.json(result.rows[0]);
  } catch (err) {
    next(err);
  }
});

Describe how you would implement user authentication in Express.js.

🇻🇳 Cách triển khai xác thực người dùng (Authentication) với JWT trong Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Xác thực với JWT (JSON Web Token) bao gồm 2 phần: (1) Endpoint Đăng nhập: Kiểm tra mật khẩu (so khớp hash bằng bcrypt), nếu đúng thì ký tạo token jwt.sign({ userId }, SECRET, { expiresIn: '1h' }) và trả về client, và (2) Auth Middleware: Đọc token từ header Authorization: Bearer , giải mã bằng jwt.verify(), gắn thông tin req.user và cho phép đi tiếp.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Lưu trữ an toàn: Khuyên dùng gửi JWT qua Cookie `httpOnly` thay vì lưu trong localStorage của trình duyệt để chống tấn công XSS.
2. Refresh Token Pattern: Sử dụng Access Token có hạn ngắn (15 phút) và Refresh Token có hạn dài (7 ngày) lưu trong database để cấp lại token mới khi hết hạn mà người dùng không phải đăng nhập lại.
💻 Code Ví Dụ Minh Họa & Output 
const jwt = require('jsonwebtoken');

// Middleware xác thực JWT
const authenticateToken = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // Định dạng: Bearer <TOKEN>

  if (!token) {
    return res.status(401).json({ error: 'Yêu cầu token xác thực để truy cập' });
  }

  jwt.verify(token, process.env.JWT_SECRET, (err, user) => {
    if (err) {
      return res.status(403).json({ error: 'Token đã hết hạn hoặc không hợp lệ' });
    }
    req.user = user; // Gắn thông tin người dùng vào request
    next();
  });
};

app.get('/api/protected/profile', authenticateToken, (req, res) => {
  res.json({ message: 'Dữ liệu bảo mật', user: req.user });
});

Luôn phân biệt rõ: Status `401 Unauthorized` (chưa cung cấp token hoặc token sai) và `403 Forbidden` (token đúng nhưng không có quyền truy cập tài nguyên).
Câu 41 Mid Authentication and Authorization

Explain how sessions are managed in Express.js.

🇻🇳 Cách quản lý phiên (Sessions) trong Express và so sánh với JWT?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Session-based Authentication lưu trữ trạng thái người dùng ở phía Server (thường là trong Redis) và chỉ gửi một Cookie chứa Session ID về cho client. Trong khi đó, JWT là Token-based hoàn toàn Stateless, toàn bộ thông tin người dùng được mã hóa ký điện tử nằm ngay bên trong token ở phía Client.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
So sánh chi tiết:
1. Thu hồi (Revocation): Session thắng tuyệt đối! Nếu muốn đá user ra khỏi hệ thống, server chỉ cần xóa key session trên Redis. JWT rất khó thu hồi ngay lập tức trước khi nó hết hạn.
2. Khả năng mở rộng (Scalability): JWT thắng vì server không tốn tài nguyên lưu trữ và truy vấn DB trên mỗi request.
3. Dung lượng: Session Cookie rất nhẹ (~32 ký tự). JWT mang theo payload nên kích thước lớn hơn (~300 - 500 bytes) gửi kèm trong mỗi HTTP request.
💻 Code Ví Dụ Minh Họa & Output 
// Minh họa thu hồi Session ngay lập tức:

How can you secure passwords and sensitive information in your Express.js app?

🇻🇳 Cách bảo vệ mật khẩu và dữ liệu nhạy cảm trong ứng dụng Express?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Bảo vệ mật khẩu đòi hỏi: (1) TUYỆT ĐỐI KHÔNG BAO GIỜ lưu mật khẩu dạng văn bản thuần (plain text), (2) Sử dụng thuật toán băm chậm có Salt như bcrypt hoặc argon2 với salt rounds thích hợp (từ 10 đến 12), (3) Không bao giờ trả về trường password trong các response JSON, và (4) Mã hóa các trường dữ liệu nhạy cảm bằng AES-256.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Tại sao dùng bcrypt thay vì MD5/SHA256: MD5 và SHA256 được thiết kế để chạy siêu nhanh, hacker có thể dùng GPU thử hàng tỷ mật khẩu mỗi giây (Brute-force). Bcrypt là thuật toán băm cố tình làm chậm CPU, kháng lại các cuộc tấn công Rainbow Table nhờ tự động thêm Salt ngẫu nhiên.
2. Tách biệt trường password: Trong ORM (Mongoose/Prisma), luôn cấu hình `select: false` cho trường mật khẩu.
💻 Code Ví Dụ Minh Họa & Output 
const bcrypt = require('bcrypt');

const SALT_ROUNDS = 12; // Chi phí băm chuẩn mực

// 1. Băm mật khẩu khi đăng ký
async function hashPassword(plainPassword) {
  return await bcrypt.hash(plainPassword, SALT_ROUNDS);
}

// 2. So khớp khi đăng nhập
async function verifyPassword(plainPassword, hashedPassword) {
  return await bcrypt.compare(plainPassword, hashedPassword);
}
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Đừng đặt salt rounds quá cao (> 14) vì nó sẽ chiếm dụng CPU quá lâu làm nghẽn Event Loop của Node.js. 10 - 12 rounds là mức cân bằng hoàn hảo.

const express = require('express');
const app = express();
app.use(express.json());

app.post('/api/reverse-payload', (req, res) => {
  const body = req.body;

  if (!body || typeof body !== 'object') {
    return res.status(400).json({ error: 'Payload phải là một đối tượng JSON hoặc mảng hợp lệ' });

  // Trường hợp là Array:

Discuss how to handle session management in a distributed Express.js application.

▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Trong hệ thống phân tán chạy nhiều instances Express phía sau Load Balancer, BẮT BUỘC phải sử dụng Centralized In-Memory Store (Redis Cluster) làm nơi lưu trữ session duy nhất thông qua connect-redis. Mọi instance Express đều kết nối vào cụm Redis này để đọc và ghi session chung với độ trễ < 1ms.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
1. Tại sao không dùng Sticky Sessions: Sticky Sessions phụ thuộc vào Load Balancer map IP user vào 1 server cố định. Nếu server đó chết, user bị đăng xuất. Dùng Redis Cluster giúp người dùng kết nối vào bất kỳ server nào cũng giữ nguyên trạng thái đăng nhập.
2. Redis Replication: Thiết lập Redis Master-Replica để đảm bảo không bị mất session khi một node Redis bảo trì.
💻 Code Ví Dụ Minh Họa & Output 
const session = require('express-session');
const { RedisStore } = require('connect-redis');
const { createClient } = require('redis');

const redisClient = createClient({ url: process.env.REDIS_URL });
redisClient.connect().catch(console.error);

app.use(session({
  store: new RedisStore({ client: redisClient, prefix: 'sess:' }),
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: { secure: true, httpOnly: true, maxAge: 86400000 }
}));
