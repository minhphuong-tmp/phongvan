Câu 1 Junior Django Fundamentals

What is Django and what are its key features?

🇻🇳 Django là gì và các tính năng cốt lõi làm nên sức mạnh của nó?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Django là một Web Framework bậc cao (high-level) mã nguồn mở viết bằng Python, tuân theo triết lý 'Batteries-Included' (đầy đủ mọi công cụ cần thiết từ ORM, Admin, Auth, Migrations đến Bảo mật) và nguyên tắc DRY (Don't Repeat Yourself), giúp lập trình viên xây dựng ứng dụng web an toàn, có khả năng mở rộng cao trong thời gian ngắn nhất.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Các tính năng cốt lõi: 1. Django ORM: Ánh xạ CSDL quan hệ sang Python Object, trừu tượng hóa SQL và chống SQL Injection. 2. Automatic Admin Interface: Tự động sinh trang quản trị dữ liệu CRUD chỉ với vài dòng cấu hình. 3. Bảo mật tích hợp: Chống mặc định CSRF, XSS, Clickjacking và SQL Injection. 4. URL Dispatcher: Định tuyến URL thanh lịch bằng Regex hoặc Path converters. 5. Template Engine: Kế thừa template linh hoạt. 6. Form Handling: Tự động render HTML form và validate dữ liệu chặt chẽ.

# Khởi tạo Django app và model trong vài dòng code:
from django.db import models

class Article(models.Model):
    title = models.CharField(max_length=200, verbose_name="Tiêu đề")
    slug = models.SlugField(unique=True)
    content = models.TextField(verbose_name="Nội dung")
    published_at = models.DateTimeField(auto_now_add=True)

        return self.title

Câu 2 Junior Django Fundamentals

Explain the MTV (Model-Template-View) architecture pattern in Django.

🇻🇳 Giải thích kiến trúc MTV (Model-Template-View) trong Django và so sánh với MVC?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Django sử dụng biến thể MTV: **Model** (Tầng dữ liệu / ORM), **Template** (Tầng giao diện / Presentation), và **View** (Tầng xử lý logic nghiệp vụ). So với MVC truyền thống: View trong Django đóng vai trò của Controller, còn Template trong Django đóng vai trò của View; bản thân Django Framework đóng vai trò điều phối viên Controller tổng.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Bảng đối chiếu MTV vs MVC:
- Model (M): Cả hai đều đại diện cho cấu trúc dữ liệu và tương tác CSDL.
- Template (T): Tương đương với View (V) trong MVC — chịu trách nhiệm hiển thị HTML cho người dùng.
- View (V): Tương đương với Controller (C) trong MVC — nhận HttpRequest, gọi Model lấy dữ liệu, xử lý logic và trả về HttpResponse kèm Template đã render.
💻 Code Ví Dụ Minh Họa & Output 
# 1. Model (models.py)
class Product(models.Model):
    name = models.CharField(max_length=100)

# 2. View (views.py) - Đóng vai trò Controller xử lý logic
from django.shortcuts import render
def product_list(request):
    products = Product.objects.all()
    return render(request, "products.html", {"products": products})

# 3. Template (products.html) - Đóng vai trò View hiển thị
<!-- {% for p in products %} <li>{{ p.name }}</li> {% endfor %} -->

What is a Django project and how is it different from a Django app?

🇻🇳 Phân biệt Django Project và Django App?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Django Project là toàn bộ hệ thống web hoàn chỉnh, chứa cấu hình tổng thể (settings.py, urls.py, middleware, kết nối DB). Django App là một module tính năng độc lập, có thể tái sử dụng (ví dụ: app authentication, app blog, app cart). Một Project bao gồm nhiều App.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Quy tắc thiết kế: 'A project is a collection of configuration and apps; an app is a written Web application that does something.' Một app tốt nên có tính gắn kết cao (high cohesion) và độc lập (low coupling), cho phép bốc sang project khác dùng lại.

Describe the purpose of the settings.py file in a Django project.

🇻🇳 Vai trò và các cấu hình quan trọng nhất trong file settings.py?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
File settings.py chứa toàn bộ cấu hình toàn cục của dự án Django. Các biến quan trọng nhất: SECRET_KEY, DEBUG, ALLOWED_HOSTS, INSTALLED_APPS, MIDDLEWARE, DATABASES, TEMPLATES, STATIC_URL, MEDIA_URL.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động

🇻🇳 Vai trò của file urls.py và cơ chế điều hướng URL trong Django?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
File urls.py là bảng điều hướng định tuyến (URLconf) của Django. Nó ánh xạ các mẫu đường dẫn URL (URL patterns) tới các hàm View hoặc Class-Based View tương ứng để xử lý request.

    # Ủy quyền toàn bộ URL bắt đầu bằng /api/ cho app 'api':
    path('api/v1/', include('api.urls')),

Explain the concept of Django’s ORM (Object-Relational Mapping).

🇻🇳 Khái niệm Django ORM và ưu/nhược điểm so với viết SQL thuần?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Django ORM là tầng trừu tượng hóa CSDL, cho phép thao tác với database hoàn toàn bằng code Python. Ưu điểm: Tăng tốc độ phát triển (RAD), độc lập với CSDL (chuyển đổi SQLite sang PostgreSQL không cần sửa code), tự động chống SQL Injection. Nhược điểm: Có thể sinh câu SQL chưa tối ưu và dễ gặp lỗi N+1 queries nếu dev thiếu kinh nghiệm.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Django ORM hỗ trợ cơ chế QuerySet Lazy Evaluation — query chỉ được thực thi khi thực sự cần dữ liệu (iteration, slicing, len). Hỗ trợ các hàm tổng hợp Aggregation (`Count`, `Sum`, `Avg`), Annotation, Subquery, F-expression và Q-expression.

What is a Django model and how is it defined?

🇻🇳 Django Model là gì và cách định nghĩa một Model chuẩn?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Model là nguồn thông tin duy nhất và chân thực về dữ liệu của bạn trong Django. Mỗi Model là một Python Class kế thừa từ django.db.models.Model, trong đó mỗi thuộc tính của class tương ứng với một cột trong bảng CSDL.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Các thành phần chuẩn của một Model chuyên nghiệp: 1. Các trường dữ liệu (Fields: CharField, IntegerField, DateTimeField, ForeignKey...). 2. Class `Meta` cấu hình bảng (db_table, ordering, indexes, constraints). 3. Phương thức `__str__()` để hiển thị tên thân thiện trên Admin. 4. Phương thức `get_absolute_url()` cho SEO.
💻 Code Ví Dụ Minh Họa & Output 
from django.db import models
from django.urls import reverse

class Customer(models.Model):
    name = models.CharField(max_length=150, verbose_name="Tên khách hàng")
    email = models.EmailField(unique=True)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ["-created_at"]
        verbose_name = "Khách hàng"
        indexes = [models.Index(fields=["email"])]

    def __str__(self):
        return f"{self.name} ({self.email})"

    def get_absolute_url(self):
        return reverse("customer-detail", kwargs={"pk": self.pk})

Câu 9 Mid Django Fundamentals

What is a Django view and how is it created?

🇻🇳 Django View là gì và phân biệt Function-Based View (FBV) vs Class-Based View (CBV)?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
View là hàm hoặc class tiếp nhận HttpRequest và trả về HttpResponse. FBV (Function-Based View) viết bằng hàm thuần túy, đơn giản, dễ đọc cho logic ngắn. CBV (Class-Based View) viết bằng class, tận dụng tính kế thừa và Generic Views (ListView, DetailView, CreateView) để tái sử dụng mã tối đa trong các bài toán CRUD chuẩn.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
So sánh FBV vs CBV:
- FBV: Luồng chạy rõ ràng từ trên xuống dưới, dễ debug, dễ dùng decorator `@login_required`. Phù hợp API hoặc logic phức tạp đặc thù.
- CBV: Tổ chức code tốt, tái sử dụng logic qua Mixin (`LoginRequiredMixin`), giảm code lặp lại 70% với CRUD. Nhược điểm: Phức tạp hơn và luồng thực thi bị ẩn trong các phương thức của class cha.
💻 Code Ví Dụ Minh Họa & Output 
# 1. FBV (Function-Based View):
from django.shortcuts import render, get_object_or_404
from .models import Customer

def customer_detail_fbv(request, pk):
    customer = get_object_or_404(Customer, pk=pk)
    return render(request, "customer_detail.html", {"customer": customer})

# 2. CBV (Class-Based View tương đương):
from django.views.generic import DetailView

class CustomerDetailCBV(DetailView):
    model = Customer
    template_name = "customer_detail.html"
    context_object_name = "customer"
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Nguyên tắc chọn: Dùng CBV cho các trang CRUD chuẩn; dùng FBV cho các endpoint tùy biến cao hoặc xử lý luồng đặc biệt.

Explain the concept of URL patterns in Django.

🇻🇳 Cơ chế URL patterns và Path Converters trong Django?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Từ Django 2.0+, path() hỗ trợ Path Converters dạng để tự động bắt tham số từ URL và ép sang đúng kiểu dữ liệu Python tương ứng trước khi truyền vào View (ví dụ: str, int, slug, uuid, path).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Các Path Converter tích hợp sẵn: 1. `int`: Số nguyên dương. 2. `str`: Bất kỳ chuỗi ký tự nào không chứa dấu gạch chéo `/`. 3. `slug`: Chuỗi chữ, số, gạch nối, gạch dưới. 4. `uuid`: Định dạng UUID chuẩn. 5. `path`: Khớp toàn bộ đường dẫn kể cả dấu `/`. Nếu cần regex phức tạp, dùng `re_path()`.
💻 Code Ví Dụ Minh Họa & Output 
from django.urls import path
from . import views

urlpatterns = [
    # Tự động ép 'order_id' thành int, nếu gõ chữ sẽ trả về 404 ngay:
    path("orders/<int:order_id>/", views.order_detail, name="order-detail"),
    # Bắt bài viết theo slug:
    path("posts/<slug:post_slug>/", views.post_detail, name="post-detail"),
]
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Bạn có thể tự tạo Custom Path Converter bằng cách định nghĩa class có thuộc tính `regex` và 2 phương thức `to_python()` và `to_url()`.

Câu 11 Junior Django Models and Database

What is a database migration in Django and why is it important?

🇻🇳 Database Migration trong Django là gì và quy trình hoạt động?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Migration là cách Django truyền bá các thay đổi trong Model (thêm trường, xóa cột, đổi ràng buộc) vào Schema của CSDL. Hai lệnh cốt lõi: makemigrations (đọc Model và sinh file migration .py) và migrate (thực thi các file migration vào CSDL).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Bản chất: Django lưu lịch sử các lần migration trong bảng `django_migrations` trong DB để biết file nào đã chạy, file nào chưa. Hỗ trợ rollback về phiên bản cũ bằng lệnh: `python manage.py migrate `.
💻 Code Ví Dụ Minh Họa & Output 
# Quy trình cập nhật DB chuẩn:

Explain the difference between a ForeignKey and a ManyToManyField in Django models.

🇻🇳 Phân biệt ForeignKey và ManyToManyField trong Django Model?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
ForeignKey định nghĩa quan hệ Một-Nhiều (1-N): Một bản ghi ở bảng A liên kết với nhiều bản ghi ở bảng B (CSDL tạo cột khóa ngoại trực tiếp ở bảng B). ManyToManyField định nghĩa quan hệ Nhiều-Nhiều (N-N): CSDL tự động sinh một bảng trung gian (Junction/Through table) gồm 2 khóa ngoại để liên kết.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Tham số `on_delete` bắt buộc trong ForeignKey từ Django 2.0: 1. `CASCADE` (xóa cha -> xóa sạch con), 2. `PROTECT` (chặn xóa cha nếu còn con), 3. `SET_NULL` (gán null), 4. `DO_NOTHING`. Với ManyToManyField, có thể dùng tham số `through='MyCustomTable'` để lưu thêm thông tin trên quan hệ liên kết (ví dụ ngày tham gia, vai trò).

    name = models.CharField(max_length=100)

class Category(models.Model):
    name = models.CharField(max_length=50)

class Book(models.Model):
    title = models.CharField(max_length=200)
    # Quan hệ 1-N: 1 Tác giả viết nhiều Sách
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name="books")
    # Quan hệ N-N: 1 Sách thuộc nhiều Danh mục, 1 Danh mục có nhiều Sách
    categories = models.ManyToManyField(Category, related_name="books")

class LowercaseCharField(models.CharField):

Describe the concept of model inheritance in Django.

🇻🇳 Các hình thức Kế thừa Model (Model Inheritance) trong Django?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Django hỗ trợ 3 kiểu kế thừa Model: 1. **Abstract Base Classes** (Lớp cha trừu tượng abstract=True - không sinh bảng trong DB, class con kế thừa các trường), 2. **Multi-Table Inheritance** (Mỗi class có bảng riêng, liên kết bằng OneToOne ngầm), 3. **Proxy Models** (Dùng chung bảng của cha nhưng thay đổi hành vi/ordering trong Python).
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
So sánh: Abstract Base Class là lựa chọn phổ biến nhất 90% trường hợp để chia sẻ các trường chung (`created_at`, `updated_at`, `is_deleted`). Multi-table inheritance ít dùng vì gây JOIN ngầm làm chậm hiệu năng. Proxy Model dùng khi cần thêm method hoặc đổi default manager mà không sửa đổi schema CSDL.
💻 Code Ví Dụ Minh Họa & Output 
from django.db import models

# 1. Abstract Base Class (Không tạo bảng trong DB)
class TimeStampedModel(models.Model):
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True  # Quan trọng!

class Post(TimeStampedModel):
    title = models.CharField(max_length=200)

# 2. Proxy Model (Dùng chung bảng Post nhưng đổi hành vi)
class OrderedPostProxy(Post):
    class Meta:
        proxy = True
        ordering = ["-created_at"]

Hầu như mọi dự án production đều tạo 1 class `BaseModel(models.Model)` có `abstract = True` chứa `id (UUID)`, `created_at`, `updated_at`.

What is the difference between select_related() and prefetch_related() in Django queries?

▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
select_related() thực hiện câu lệnh SQL INNER JOIN (hoặc LEFT OUTER JOIN) để lấy toàn bộ dữ liệu liên kết ngay trong MỘT câu truy vấn duy nhất, dùng cho quan hệ đơn: **ForeignKey (1-N)** và **OneToOne (1-1)**. prefetch_related() thực hiện các câu lệnh SELECT độc lập cho từng bảng rồi JOIN lại bằng Python trong bộ nhớ, dùng cho quan hệ đa: **ManyToManyField (N-N)** và **Reverse ForeignKey**.

Cả hai đều giải quyết triệt để lỗi kinh điển N+1 Queries: Thay vì bắn 1 câu query cha + N câu query con (gây nghẽn DB và sập server), `select_related` chỉ bắn đúng 1 query, còn `prefetch_related` chỉ bắn 2 query (1 query bảng cha + 1 query bảng con có mệnh đề `WHERE id IN (...)`).

articles = Article.objects.prefetch_related("tags").all()

Describe the concept of database transactions in Django.

🇻🇳 Khái niệm Database Transactions và cách sử dụng transaction.atomic() trong Django?
▾
🎯 Tóm Tắt Trọng Tâm Phỏng Vấn (30s Pitch)
Database Transaction đảm bảo tính chất ACID (Atomicity, Consistency, Isolation, Durability) — tất cả các thao tác CSDL trong khối giao dịch hoặc là cùng thành công mỹ mãn (Commit), hoặc nếu có bất kỳ lỗi nào xảy ra thì toàn bộ sẽ được khôi phục về trạng thái ban đầu (Rollback). Trong Django, ta sử dụng context manager hoặc decorator @transaction.atomic.
🔍 Giải Thích Chuyên Sâu & Cơ Chế Hoạt Động
Ứng dụng trong thanh toán / chuyển tiền ngân hàng: Trừ tiền tài khoản A và cộng tiền tài khoản B. Nếu sau khi trừ A mà server mất điện trước khi cộng B, không có transaction sẽ làm mất tiền của user! `@transaction.atomic` đảm bảo nếu bước B fail, bước A tự động được hoàn tác (rollback).
💻 Code Ví Dụ Minh Họa & Output 
from django.db import transaction

def transfer_money(sender_acc, receiver_acc, amount):
    # Khối giao dịch nguyên tử:
    with transaction.atomic():
        sender_acc.balance -= amount
        sender_acc.save()

        # Giả lập nếu xảy ra lỗi bất ngờ tại đây:
        if amount > 100_000_000:
            raise ValueError("Vượt hạn mức chuyển tiền một lần!")

        receiver_acc.balance += amount
        receiver_acc.save()
    print(" Chuyển tiền thành công!")
💡 Điểm Cộng & Bẫy Phỏng Vấn (Gotchas / Senior Tips)
Tuyệt đối không bọc các cuộc gọi mạng HTTP bên ngoài vào trong khối `atomic()`, vì nếu API bên ngoài chạy chậm (lag), CSDL sẽ bị khóa lock dòng/bảng quá lâu làm nghẽn toàn hệ thống.
